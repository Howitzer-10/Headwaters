## Part 2: Ticket

### HDW-511 · Tool-schema cost: honest diagnosis and opt-in prune-to-fit
**Model** Sonnet · **Effort** Medium · **Depends** 137, 304 · **Class** Core · **Refs** D7, D14, D16
**Build:**

Slice A — honest diagnosis (always on).
- When routing fails for want of context on a tool-heavy request, the error states the real
  composition (total `est_tokens`; tools vs message/system text vs images; the largest
  contributors by namespace) and the fixes that actually work: a wider scope such as
  `headwaters/auto`, the new prune setting, or dropping a large MCP server.
- Never emit a `pull <model>` hint when the shortfall is context, not availability. Keep the
  hint when a model genuinely is not installed.
- Must hold for the local-only case that produced the dogfood message.

Slice B — prune-to-fit for non-`headwaters` tools (opt-in, default off).
- When local candidates are excluded only by tool-schema volume, drop tool schemas so a local
  model fits. Never drop namespace `headwaters`. Never prune on free or cloud tiers. Never
  prune when images or message text alone exceed the budget.
- Attribute each tool to a namespace deterministically: split on `__` when present, otherwise
  the longest shared prefix of the remaining names. Ambiguous attribution refuses to prune and
  returns the slice-A error. Fail closed.
- Default OFF via config, documented where other policy settings are documented. When off,
  behaviour is exactly today plus the better message.
- When on and pruning would help: smallest set of drops that makes a local candidate pass the
  existing filters, largest namespaces first, then re-run the normal decision path. Record the
  drops in the decision reasons so `headwaters explain` and the dashboard show them.
- If no local model fits after dropping every non-`headwaters` tool, do not prune; return the
  slice-A error.
- Only the pruned local path sees pruned tools, and the pruned request is what is forwarded.

**Accept when:**
- A tool-heavy local-only request of ~57.8k `est_tokens` reports total, tools, message/system
  and image shares, names the largest tool namespaces, and carries no `pull <model>` hint.
- With `tools.prune_to_fit: false` (default) every existing routing result is unchanged.
- With it true, a request that no local model could hold is served locally after dropping only
  non-`headwaters` namespaces, and the decision reasons record what was dropped.
- Ambiguous attribution and "nothing fits even after pruning" both fail closed with no mutation
  of the request.
- Free and cloud tiers are untouched.
- ruff, mypy, lint-imports and the full pytest suite pass.

## Part 3: Design material

### Excerpt: dogfood evidence (HDW-511)

Cline (desktop) with two MCP servers enabled, alias `headwaters/local`, three-word prompt:

```
The run failed: Only local models are allowed here, but none is available. pull qwen2.5-coder:14b
```

Measured composition of the recorded request:

| Part | Chars | est tokens |
|---|---|---|
| summer-engine tools (109) | 154,950 | ~44,271 |
| headwaters tools (8) | 8,481 | ~2,423 |
| Cline built-in tool schemas | ~40,000 | ~11,000 |
| system prompt | 4,265 | ~1,200 |
| user message | ~18 | ~5 |
| **request total** | | **57,794** |

`headwaters/core/analyzer/requirements.py` adds `len(dumps(tools))` to the code-rate token
estimate, so the tool array sets `est_tokens` and therefore `hard.min_ctx`. With
`ctx_headroom` 1.2 the need is 69,353, above the largest `local.ctx_steps` entry (65,536),
so `fit.usable` is false, `local_usable` is false, and `resolve_scope` raises
`local_unavailable` — even though 128k-context models are installed. The `pull` hint names
a model that is already installed: it is a size suggestion, not a missing model.

### Excerpt: constraints

- Only the diagnosis and the opt-in prune change; the ladder, scoring, walls and scope locks
  are untouched.
- Local scope stays fail-closed: pruning never widens the tier set and never touches locks.
- The `tools` array carries no server field, so attribution is a heuristic that must fail
  closed rather than guess.
- `headwaters pick ... --tools` sets a boolean without schemas; reproduce large-tool requests
  with a real `tools` array.

### Deferrals (recorded in docs/reports/HDW-511.md, not built here)

- Host-side MCP server names in the OpenAI request (would remove the attribution heuristic).
- Auto-tuning `local.ctx_steps` or quantisation from the measured composition.
- Dashboard rendering of composition beyond the decision reasons.
