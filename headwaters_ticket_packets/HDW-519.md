## Part 2: Ticket

### HDW-519 · Free access is not a tier

**Model** Sonnet · **Effort** Medium-High · **Depends** HDW-514 (providers as data), HDW-111
(quota tracker) · **Class** catalog + schema + one display surface; no ★ · **Refs**
`docs/PROVIDERS.md`, `docs/DECISIONS.md` D18/D19, `docs/SDK_FACTS.md:96-117`

**Goal:** make the catalog able to say, truthfully and at the same time, "this provider sells
usage" **and** "this provider offers free model access", and give `free_limits` a shape that can
hold the five different kinds of free allowance real providers publish — without letting it
become a free-form notes column, and without changing what any existing catalog does.

**This is a data and schema ticket.** It adds fields, rows and one formatting function. It does
not add a rate limiter, a billing check, a licence gate, or a new tier name.

### The decision this ticket encodes

> A provider's **commercial character** (`charges_money`) and its **free access**
> (`free_access`) are separate fields with separate consumers. `tier` remains, required and
> unchanged in meaning — "the tier of a model this provider does not mark" — so a catalog that
> has not been migrated keeps today's behaviour exactly. Rate limits move from
> `rpm`/`rpd` scalars to a list of clauses that name a metric, a window and a scope, so
> per-organisation quotas, monthly token allowances, daily Neurons budgets and conditional
> allowances can be written down; **only request counting is implemented, and even that is
> advisory, not enforced.**

#### D1 · The split: two fields, one derivation shim

`headwaters/core/catalog/schema.py`, `ProviderEntry` (`:159`):

| Field | Type | Required | Meaning |
| --- | --- | --- | --- |
| `tier` | `ProviderTier` | **yes, unchanged** | The tier of a model this provider does **not** mark. Kept for compatibility and still read as the fallback source for `free_access`. |
| `charges_money` | `bool \| None` | no, default `None` | `true` when using this provider beyond any free allowance costs the person money. The D19 **paid-tier** sense, applied to a provider. `false` only where no money can change hands (`nvidia` prototyping). |
| `free_access` | `Literal["none","marked","all","plan"] \| None` | no, default `None` | How the free path is identified. The D19 "free model access" sense. |

`free_access` values, each with a case that forces it:

| Value | Meaning | Forced by |
| --- | --- | --- |
| `none` | No free path we can call. | `pollinations`, `opencode` (app-only, `engine.py` refuses), `opencode-go` |
| `marked` | Some models are free and the provider's own listing says which (`:free` suffix, `isFree`, `is_free`). | `kilo` (`:free`, keyless), `huggingface` (`is_free`), OpenRouter (`:free`) |
| `all` | Every model this provider serves is free for everyone, with no plan distinction. | `nvidia` (prototyping only, no billing) |
| `plan` | Every model is free **while the key is on the provider's free plan**; the catalog cannot see which plan a key is on. | `mistral` (free/experiment tier), and the four new free-tier providers |

`plan` is the value the brief does not ask for and the design needs: Groq, Gemini, Cerebras
and Cloudflare do not mark free models, they *are* free on a plan. Folding them into `all` would
claim no money can change hands; folding them into `none` restates the owner's complaint.
`plan` says the honest thing, and D1.4 says what routing does with it.

Rules of the split:

1. **Derivation shim, one function, no duplication.** A method on `ProviderEntry` (e.g.
   `labels() -> ProviderLabels(charges_money, free_access)`) computes the effective pair. When a
   field is `None` it derives:
   `charges_money = (tier == "paid")`;
   `free_access = "all" if tier == "free_cloud" else ("marked" if honor_free_markers else "none")`.
   These two expressions are exactly `_registry_tier` (`sources.py:318-330`) and the display
   label. **Every consumer reads the derived pair and never `tier` directly** — including
   `sources._registry_tier`, which becomes a mapper over `entry.labels().free_access`: `all` →
   every model `free_cloud`, `plan` → every model `free_cloud` (D1.4), `none` → every model
   `paid`, `marked` → the existing per-model marker test, unchanged.
2. **`tier` is not removed.** Removing it needs a schema bump, a decision and a signed-catalog
   migration story; none of that is here. Its docstring gains "the tier of an **unmarked**
   model; see `free_access` for marked and plan-gated free access".
3. **Explicit beats derived, always.** `groq` sets `tier: "free_cloud"` **and**
   `charges_money: true` — the literal case that the old scalar could not express: the same
   model ids are free on the free plan and billed on the dev plan. A consistency test asserts
   two one-way invariants for the seed rows: an `all` free access requires `tier: "free_cloud"`
   (if everything is free there is no paid band), and a `free_cloud` tier requires
   `free_access` in `{all, plan}` (a `free_cloud` tier that only marks some models would
   contradict itself). `paid` + `plan` (`mistral`) and `paid` + `marked` (`kilo`) are both legal.
   No test asserts `charges_money == (tier == "paid")`, because that equality is exactly what
   this ticket exists to break.
4. **`plan` routes as `free_cloud`.** A `plan` provider's models get `free_cloud` from
   discovery, so `headwaters/free` may use them. **Residual risk, stated rather than hidden:** a
   key that is on a *paid* plan will be billed, and nothing in the catalog or the API can tell
   the two apart (`docs/SDK_FACTS.md:110` for Mistral; the same absence holds for the four new
   rows and is a probe item, not a fact). The mitigation is one follow-up, not a field: record
   the key's plan (`headwaters keys set --plan free|paid`) and let `free` scope skip `plan`
   providers whose key is marked paid. Until that exists, `plan` is documented as
   "free if your key is on the free plan". `plan` and `all` therefore route identically today and
   differ only in `charges_money` and in what a future per-key plan check can exclude. If the
   build session prefers three values, collapsing `plan` into `all` plus `charges_money: true` is
   an acceptable variant **only** if the residual-risk sentence above survives verbatim in
   `docs/PROVIDERS.md` and the report; a collapsed row that reads "free" is the defect this ticket
   exists to remove.
5. **The label is formatted once.** `charges_money` + `free_access` render through a single
   function next to the model (e.g. `format_access(charges_money, free_access) -> str` →
   `"free to use"`, `"sells usage · free models marked"`, `"sells usage · free on the free plan"`,
   `"sells usage"`), importing the same vocabulary. `headwaters/core/keys.py:178`
   `ProviderInfo(name, key_required, entry.tier)` becomes `ProviderInfo(name, key_required,
   entry.labels())`, and the two built-in branches that pass a literal tier today
   (`keys.py:176` `"paid"` for reserved names, `keys.py:181` `"free_cloud"` for
   `openai_compatible` endpoints) go through the same formatter instead — otherwise three of the
   four strings still live as literals. The CLI/tray/dashboard print the formatted string, and a
   D18 test asserts the four strings appear in one module.

#### D2 · What happens to a catalog that has not been migrated

- **Behaviour is byte-identical.** Both fields absent → the derived pair equals today's
  `_registry_tier` result for every row (`all` for `free_cloud`, `marked`/`none` by
  `honor_free_markers`), and `charges_money` equals today's `tier == "paid"`. Discovery output,
  model tiers, `ProviderInfo` and quota behaviour do not change. A test fixture holds a
  pre-change copy of `seed_catalog.json` and asserts the derived triples match for all seven rows.
- **No warning, no deprecation error.** A third-party or older catalog loads quietly. Being
  un-migrated is legal, not broken. `docs/PROVIDERS.md` says so, and the seed itself is fully
  migrated so the shipped path is the explicit one.
- **Forward compatibility is one-directional and must be reported.** `_Model` sets
  `extra="forbid"` and nothing reads `schema_version` (`schema.py:295` is the only occurrence in
  the package), so an **older** build reading a **newer** catalog fails validation with a field
  error — loud, but not explained. Do not paper over it: the report records it as a known
  limitation, and Part 3 defers version negotiation (loader compares `schema_version` to a
  supported constant and prints "catalog is newer than this build" before pydantic's message).
  Practical exposure is small because `catalog/seed_catalog.json` ships in-repo and is signed
  (`headwaters/core/catalog/trust.py`); the risk is user-supplied catalogs.

Rules for the table:

1. **No invented URL.** Every `base_url` above is quoted from the vendor's own OpenAI-compat
   page. Anything that could not be quoted says `UNVERIFIED - probe required` **and the row is
   not written**. The only row in that state is Cloudflare (D4.2). GitHub Models is not a row at
   all (D4.1).
2. **Cloudflare is blocked by the account-id path.** `base_url` must carry
   `/accounts/{account_id}/`, `engine.py:106` uses `base_url` literally, and the schema pattern
   accepts braces, so the failure would be a confusing 404 at call time. Two fields fix it and
   this ticket specifies them: `base_url_vars: dict[str, str]` on `ProviderEntry` (template name →
   env var name, e.g. `{"account_id": "CLOUDFLARE_ACCOUNT_ID"}`) and a substitution in
   `TargetBuilder._cloud_target` that raises a named `ExecutorError` when a var is unset. If the
   build session judges the executor change too large for this ticket, the **correct** outcome is
   to ship the other four rows and the `free_limits` work, and leave `cloudflare` out with the
   blocker written down — **not** to ship a row that cannot be called.
3. **`gemini`, not `google`.** The wall patterns already name `gemini`; a second name for one
   provider is the D18 defect this repo already fixed once. Env var `GEMINI_API_KEY` (or the
   build session's probe result, if Google documents a different conventional name).
4. **GitHub Models is retired — the brief asks for it, and this packet says no.** As of the
   vendor's own page (`docs.github.com/en/github-models`) the playground, model catalog,
   inference API and BYOK are **no longer available**; the retirement date is stated as
   30 July 2026. Registering it would add a row whose every call fails. The packet therefore
   **does not add a `github-models` row** and records the disagreement in Part 3. If the probe
   finds the page changed, add the row then, with `key_required: true`, `env_var: GITHUB_TOKEN`
   (PAT), and `free_access: plan`.
5. **Two rows may share a name with a wall pattern only if they are the same provider.** Check
   `wall_patterns` before choosing each `name`; if a pattern exists under a different spelling,
   use the pattern's spelling.

#### D5 · `free_limits`: clauses with a metric, a window and a scope

`FreeLimit` (`schema.py:86`) keeps `provider`, `model`, `rpm`, `rpd`, `verify` and gains:

| Field | Type | Default | Meaning |
| --- | --- | --- | --- |
| `limits` | `list[LimitClause]` | `[]` | The real allowances. Empty means "legacy row: interpret `rpm`/`rpd`". |
| `licence` | `Literal["unstated","commercial_ok","non_commercial_only"]` | `"unstated"` | A restriction routing must be able to respect. Only Cohere's trial key needs `non_commercial_only` today. |
| `source_url` | `str \| None` | `None` | Provenance for the row, matching `ProviderEntry.source_url` (https pattern). |

```python
class LimitCondition(_Model):
    fact: Literal["account_topup_usd_total"]   # closed set; add a member with a test
    op:   Literal[">=", ">", "=="]
    value: float

class LimitClause(_Model):
    metric: LimitMetric   # "requests" | "tokens" | "neurons" | "usd"
    max: float            # > 0
    per: LimitWindow      # "minute" | "hour" | "day" | "month"
    scope: LimitScope     # "model" | "key" | "user" | "organisation" | "account" | "ip"
    tokens: Literal["input+output", "output"] | None = None   # tokens only
    condition: LimitCondition | None = None
    verify: bool = False
    note: str | None = None
```

Both enums live next to the type and the JSON Schema is regenerated from them
(`python -m headwaters.core.catalog.loader --check`).

The five cases the brief requires, and nothing about them is free-form:

| Provider | Clauses | Why the shape survives |
| --- | --- | --- |
| **OpenRouter** | `{requests, 20, minute, key}`; `{requests, 50, day, key}`; `{requests, 1000, day, key, condition: {account_topup_usd_total, >=, 10}, verify: false}` | A conditional is a **clause**, not an exception. |
| **Groq** | `{requests, 30, minute, organisation}`; `{requests, 1000, day, organisation}`; `{tokens, …, minute, organisation}` | `scope: organisation` is a value, not a note. |
| **Cloudflare Workers AI** | `{neurons, 10000, day, account}` | `metric: neurons` — the unit is not a request at all. |
| **Mistral** | `{tokens, 1_000_000_000, month, key, tokens: "input+output", verify: false}`; `{requests, <lower rpm>, minute, key}` | A monthly token allowance in the same list as a per-minute request cap. |
| **Cohere** | `{requests, 20, minute, key}`; `{requests, 1000, month, key}`; row `licence: non_commercial_only` | A licence is a **restriction**, not a limit, so it is on the row, not in `limits`. |

Governing rules (each gets a test):

1. **Legacy conversion.** If `limits` is empty, `rpm`/`rpd` are read exactly as today and
   resolve in memory to `{requests, rpm, minute, scope: model}` and
   `{requests, rpd, day, scope: model}`. `scope: model` is chosen because today's counter subject
   **is** the model, not because it is correct; the conversion preserves behaviour, it does not
   bless it.
2. **Most permissive applicable clause governs**, within a `(metric, per)` group. That is how
   OpenRouter's 50/day and 1000/day coexist after a top-up, and it is why a conditional clause is
   always an **extra** allowance and never a restriction.
3. **`scope` names the counting subject**: `model` → `model:<id>` (today), `key`/`user` →
   `key:<alias>`, `organisation`/`account` → `provider:<name>` (the closest observable thing —
   no org id exists in discovery; the approximation is documented), `ip` → `provider:<name>`
   (Kilo's "200 requests/hour per IP", `docs/SDK_FACTS.md:115`).
4. **Grouping change is intentional.** Migrating `openrouter` and `nvidia` to `scope: key`
   tightens counting from "20 rpm *per model*" to "20 rpm *across the key*". Nothing is enforced,
   so the only visible effect is earlier soft-ranking. It is listed in the report, tested, and
   must not be smuggled in as a "no behaviour change".
5. **The row's `verify` stays what it was; a new claim carries its own `verify: false`.** The
   OpenRouter rpm/rpd are verified; the $10→1000 condition is not, so the clause says so. Do not
   downgrade a verified row because an unverified clause joined it.

#### D6 · What the router actually reads (the anti-assumption table)

| Field | Consumed by | Effect today |
| --- | --- | --- |
| `providers[].free_access` (derived) | `catalog/sources._registry_tier` | Chooses `free_cloud` vs `paid` for every discovered model. **Routing.** |
| `providers[].tier` | derivation fallback; `keys.ProviderInfo` | Label + fallback. |
| `providers[].charges_money` | display only | A label. No routing, no billing check. |
| `providers[].base_url` / `env_var` / `key_required` / `skip_id_pattern` / `refuses()` | `TargetBuilder`, `KeyStore` | What is called, with which key. |
| `providers[].free_notes` | **nobody** | Documentation. Never parsed, never enforced. Say this in `docs/PROVIDERS.md`. |
| `free_limits[].rpm`/`rpd` (legacy) | `QuotaTracker._limit_for` | Counted per model; ≥90% of a cap (`WallsRules.soft_exhaust_pct`, `rules.py:182`) marks `soft`; scoring subtracts a penalty. **Never blocks.** |
| `free_limits[].limits` | new resolver in `QuotaTracker` | Only `metric: requests` is counted. `tokens`, `neurons`, `usd` are stored, validated, and **inert**. |
| `free_limits[].licence` | **nobody** | Documentation. `free` scope cannot refuse a non-commercial key, because no request carries a "commercial use" intent. |
| `free_limits[].verify`, `source_url`, `note`, `condition` | **nobody at runtime** | Provenance. |

**State this plainly in the code comment and the docs:** *rate limits are not enforced per
request anywhere in this codebase.* A `soft` model is still called; the quota tracker records and
ranks, it does not veto. Anyone who reads a `rpm: 20` and assumes a 21st call in a minute is
refused is wrong, and this ticket must not leave that impression in a docstring or a UI string.

`licence: non_commercial_only` is the one field here that a **correct** router would act on and
cannot. Two candidate designs, both out of scope: a per-request `commercial_use` flag set by the
caller, or a per-key declaration (`headwaters keys set --use non-commercial`) that `free` scope
honours. If the build session wants to make licence meaningful, that is a **new decision** (D20,
Part 1b) and a separate ticket — not a rider on this one.

  subject; counting never vetoes, and the subject is a provider-name approximation.
- "Neurons/tokens/month are respected" — cannot pass. No token or neuron accounting exists;
  those clauses are inert by design in this ticket.

- **Rate-limit enforcement** (turning `soft` into a refusal, or a pre-flight check per request).
