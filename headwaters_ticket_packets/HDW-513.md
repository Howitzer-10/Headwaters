## Part 2: Ticket

### HDW-513 · Cascades remember what failed and reach a healthy tier
**Model** Sonnet · **Effort** Medium · **Depends** 117, 510 · **Class** Core · **Refs** live evidence, D10, D11, D17 (new)

**Defect (live, from the state database).** A Cline user set the model to `headwaters/auto` and
sent one prompt: `Just testing model, so reply "Hello, Jim"`. Cline showed
`The run failed: Every allowed attempt failed.` 21 minutes later. The prompt was trivial; the
tools payload made it a 14,680-token code request.

Decisions 9, 10, 11 and 12 (one session, ~50 s apart) recorded identical requirements
(`est_tokens` 14680, `hard.tools` true, `soft.task` `code`, complexity 3, floor 100.0) and the
same chosen model on every attempt: `google/gemma-4-26b-a4b-it:free`. The alternatives were the
four `:free` models already marked `provider_error`, then every other `:free` model, then **every
local model last**. `router.max_attempts` is 4. There are no cloud keys on the machine at all
(`headwaters keys list` shows anthropic, openai and openrouter "not set"; a keyless OpenRouter
call returns HTTP 401 `{"error":{"message":"No cookie auth credentials found","code":401}}`).
So all four attempts were doomed to the same 401, while a healthy local model had answered the
same gateway 90 s earlier (decision 8, `qwen3-vl:8b-instruct`).

Two distinct defects turned a fast, explainable failure into 21 minutes and a useless message:

1. **No per-request failure memory.** `RouteRun.excluded` exists but is only consulted on the
   cascade path. It does not distinguish failure classes, does not skip a provider that just
   rejected every call for lack of a key, and records nothing a user can read. A request can
   therefore spend every allowed attempt inside the same dead provider.
2. **Tier ordering starves the local tier.** `build_ladder` concatenates rungs: all cheap cloud
   candidates (which score higher) precede all local candidates. With `max_attempts` 4 and a
   dead free tier, no attempt can ever land on local.

Both surface as one opaque string, `Every allowed attempt failed.`, with nothing saying the cause
was a missing API key rather than model quality.

**Build.**

**Slice A — per-request failure memory.**
- Add a per-request exclusion record to `RouteRun` (`headwaters/core/router_run.py`): model id,
  tier, provider, failure class, status. It is created per request and discarded with it. It is
  **not** a cooldown: nothing is written to `walls.py`, `quotas.py` or SQLite state. The existing
  global wall/backoff machinery (HDW-511) stays exactly as it is; this must neither duplicate nor
  contradict it.
- Classify each `ExecutorError`: `auth` / `auth_missing_key` (401/403), `provider_error`,
  `connection_error`, `timeout`, `context`, and the wall kinds. `provider_error`, `auth`,
  `context`, `connection_error` and `timeout` make a model unusable **for this request**
  (the payload does not change), so it is excluded. A `context` failure must never become a
  global wall: the same model may serve a smaller payload on a later request. `rate_limit` and
  `overloaded` keep their existing retry-then-cascade behaviour; the model is excluded only once
  the retry path is done.
- A later attempt of the same request must never choose a model already excluded in that request.
  Add one clear line to the decision reasons on every re-decision, e.g.
  `attempt 2 of 4: skipping 4 models that already failed in this request`.
- When an `auth` failure happens for a provider and the key store says no key is configured
  (`Executor.key_present(provider) is False`, cached by `KeyStore`, no network), exclude every
  candidate of that provider for this request in one step and note it. This is the cheap,
  cached fast-fail; it must not add a network call to the hot path. It also records the failure
  as `auth_missing_key` rather than a generic `provider_error`.
- `max_attempts` remains the ceiling for every attempt of one request.

**Slice B — tier fairness / local fallback.**
- Apply a deterministic tier-interleave to the ladder in `headwaters/core/policy/ladder.py`,
  after the rungs are built and de-duplicated and before the decision is taken:

  1. Partition the ladder into one queue per tier, preserving each queue's existing order. Within
     a tier the best remaining candidate is therefore first (floor, rung and score are already
     encoded in that order).
  2. Order the queues by first appearance in the unmodified ladder — the ranked preference.
  3. Emit round-robin: queue A head, queue B head, queue C head, A second, B second, ...
  4. The first entry is unchanged, so the initial decision and `primary_first` are unchanged.

  This guarantees, given `max_attempts >=` the number of tiers with candidates, that every
  available tier is tried before any tier takes a second attempt. When `max_attempts` is smaller,
  the earlier-ranked tiers win, and the terminal error names the tier that was never tried.
  Re-deciding after an exclusion re-partitions the remaining candidates, so the guarantee holds
  across the whole request, not just the first decision.
- The interleave only reorders candidates that already passed the hard filter: it never adds a
  tier, so scope, locks, privacy and airplane mode are unchanged.
- Record the interleaving in the decision reasons (e.g.
  `tier fairness: free_cloud, local interleaved (one attempt per tier first)`).
- Write the rule into `docs/DECISIONS.md` as **D17** (binding): tier fairness and per-request
  failure memory are core routing rules, not plugin behaviour.

**Slice C — an honest terminal error.**
- Replace `Every allowed attempt failed.` (and the bare `No other model can serve this request in
  the current scope.` when attempts ran out) with a bounded, actionable message:
  1. If any failure is authentication/missing-key, name the provider, the fact that no key is
     configured or the credential was rejected, and the exact fix command, e.g.
     `No OpenRouter API key is configured; OpenRouter rejected the request without one (401). Save one with: headwaters keys set openrouter`.
  2. List every attempt on one line: `attempt N: model (tier, provider) - failure class: short reason`.
     Cap the list (5 lines) and say `and N more` so a chat host stays readable.
  3. Redact credential-looking substrings from anything upstream before echoing it (`sk-...`,
     `Bearer ...`, `api_key=...`, long provider tokens). Key material is never echoed.
  4. When an available tier was never tried (for example local models were in scope but every
     attempt went to the dead free tier), say so explicitly.
  5. Keep the message bounded to a handful of lines; it is shown in Cline and other chat hosts.
- The message is produced in one place so the OpenAI and Anthropic faces cannot disagree
  (`headwaters/gateway/shared.py` already owns refusal meaning).

**Accept when:**
- A model that failed earlier in the same request is never chosen again by a later attempt.
- Two tiers are available, the first tier is dead, and a later attempt lands on the second tier.
- A dead tier cannot consume every allowed attempt while another tier has a usable candidate.
- The terminal message names the missing key and the exact `headwaters keys set <alias>` command.
- Credential-looking substrings are redacted from the terminal message.
- An unauthenticated cloud provider is recorded as `auth_missing_key`/`auth`, not
  `provider_error`.
- A context failure does not create a wall or exclude the model from a later request.
- The existing ladder, scope, lock, stickiness and escalation tests pass unchanged.

**Tests** (`tests/`):
- same-model re-selection prevented across attempts;
- a dead tier cannot consume all attempts;
- local reached after a dead free tier;
- terminal message naming the missing key and the fix command;
- credential redaction;
- unauthenticated cloud provider recorded as such rather than as a generic model failure;
- context failure is per-request only (a second request may pick the model again).

**Non-goals:** do not enable `paid_scopes`; do not add providers or keys; do not change Cline's
configuration; do not touch tools pruning or the HDW-511 composition error; do not edit
`headwaters_ticket_packets/HDW-511.md` or `HDW-512.md`; do not push or merge.

### Why the interleave is safe

- The ladder rungs already encode everything the product promises: floors, best effort,
  optimistic only with escalation, `primary_first`, local-only states, the free-router cap.
  Interleaving reorders those entries; it never introduces one the rungs did not admit.
- Re-deciding after each failure operates on the remaining candidates, so a tier that just
  failed cannot be "skipped forever" by a stale precomputed order: the queue is rebuilt without
  the failed model, and the rotation starts after the tier that was attempted last
  (`PolicyRequest.tier_attempts` carried from `RouteRun.attempts`), so the failing tier cannot take
  the next attempt while an untried tier is still waiting. Without that carry the rota would restart
  at the fresh head of the same tier, which is exactly the starvation HDW-513 fixes.
- A tier contributes one entry per turn, always its best-scoring remaining candidate, so fairness
  never reorders inside a tier and never outranks the policy's own score order.
- Determinism comes from `rank_candidates` (already deterministic) plus first-appearance queue
  order. No clocks, no randomness, nothing to seed in tests.
- The guarantee is behavioural, not a promise about attempts in excess of the tier count:
  `max_attempts` still wins, and the terminal error names any tier that never got its turn.
