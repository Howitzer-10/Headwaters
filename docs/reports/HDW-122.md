## Summary
Credit walls are now recorded per credit class, so one paid OpenRouter 402 writes `provider:openrouter:paid` and no longer blocks `:free` models (HDW-119 F3, probe P9). An exhausted wall with no reset time now ends after the new rule `walls.exhausted_recheck_s` (default 900 s). The executor exposes the key alias, the router passes it with the tier to the quota tracker, and `count_request` also runs on HTTP 429 (F22).

## Files changed
- headwaters/core/quotas.py: `credit_class` / `credit_subject`; `record_wall` and `availability` take an optional `tier`; exhausted walls get `until = now + exhausted_recheck_s`; `mark_balance_ok` and a failing `poll_key` act on the paid class only.
- headwaters/core/rules.py: new `walls.exhausted_recheck_s` (default 900, > 0).
- headwaters/core/executor/executor.py: optional `key_alias_for` callback and `Executor.key_alias(provider)`.
- headwaters/core/router.py: passes key alias and tier to `availability`, `record_wall`, `record_success`; counts a request on a 429 failure.
- catalog/rules.schema.json: regenerated for the new rule.
- docs/ASSUMPTIONS.md: one new row for HDW-122.
- tests/router_rig.py: `key_alias_for`, `free_limits`, `clock` arguments and a `quotas` handle.
- tests/test_quotas.py: old "never expires" test rewritten; recheck and credit-class tests added.
- tests/test_router_walls.py: new router and executor tests for this ticket.
