## Summary

`headwaters-vscode` now has a status bar item and the commands the ticket names, on top of the
language model provider HDW-506 built. The item shows tier, warm model, active walls, savings and
the purple Private Mode lock, and clicking it opens the dashboard. It reads **two** existing daemon
surfaces and adds no third: `GET /v1/status` for tier, warm model, walls, scope and `private_lock`,
and the `headwaters_status` MCP tool for savings and the pinned model — that tool is the only JSON
surface carrying savings, and a switched-off or absent ledger answers `available: false` rather than
failing. When the daemon dies or the token stops being accepted, the item becomes
`$(error) Headwaters — daemon not reachable` on the next tick: it never leaves the previous numbers
on screen pretending to be current.

The extension also became packageable: `repository`, narrowed `categories`, an extension-local
`LICENSE`, `README.md`, `CHANGELOG.md`, `.vscodeignore`, `@vscode/vsce` as a devDependency and a CI
packaging job. The VSIX installs into the real VS Code on this machine and the commands execute in
the real extension host. Publishing itself is not done and cannot be done here: it needs a
Marketplace PAT or an Open VSX token, and the report says so instead of pretending.

Pin and handoff — the two places where a lie was easiest — are handled by stating the real scope:
`Pin Model` writes `mcp.pinned_model`, which affects **front-door MCP tool calls only**, and says so
in its prompt, its confirmation and the tooltip; there is no "open handoff" command because nothing
in the daemon can re-open a stored packet, so the command creates one and says the packet id is the
only handle.

## Decisions (for promotion to `docs/DECISIONS.md`)

Recorded here, not in `docs/DECISIONS.md`, which is shared and a landing-time edit. Numbered
`D-507-n` so they cannot be confused with the existing D-series.

- **D-507-1 — Pin is kept, and its real scope is printed on every surface that mentions it.**
  `headwaters_pin_model` writes the kv key `mcp.pinned_model` and affects **front-door MCP tool
  calls only**; traffic through the gateway's OpenAI/Anthropic routes pins per request
  (`x-headwaters-pin` with an explicit model). The command exists because the effect is real, and
  the limitation is in its input prompt, its confirmation message and the status bar tooltip. A pin
  badge alone would have implied the gateway; there is no badge, and the pinned model is a tooltip
  row labelled "front-door MCP tool calls only".
- **D-507-2 — There is no "open handoff" command; there is "Create Handoff Packet".** `headwaters
  handoff` writes a packet, and `headwaters_handoff` (MCP) is the same write; nothing in the daemon
  can re-open, list or address a stored packet, and no packet id is retained anywhere the extension
  could read. A command that appeared to open one would open nothing. The command therefore asks for
  a goal, calls the tool, opens the packet document the tool returned, and says the packet id is the
  only handle (FU-507-1).
- **D-507-3 — Two status sources, no aggregate, and the item may be half-live.** `GET /v1/status`
  feeds tier, warm model, walls and the lock; MCP `headwaters_status` feeds savings and the pinned
  model. If the MCP call fails, the snapshot stays `live` with `savings.state === 'unavailable'` and
  the reason in the tooltip, because losing the tier to an unrelated MCP failure would be a worse
  lie than a dash next to a working tier. If `/v1/status` fails, the whole item is unavailable.
- **D-507-4 — `—` and `$0.00` are different facts and never collapse.** `formatSavings(null)` is
  `—`; a real zero from `totals.estimated_savings_usd` is `$0.00`; a sub-cent non-zero is
  `< $0.01` / `-< $0.01`. The tooltip says which one is being shown and that savings is an estimate
  against one reference model.
- **D-507-5 — A failed read replaces the numbers; it never decorates them.** On daemon death, an
  unreadable state file, an unbound API port or a rejected token, the item text becomes
  `$(error) Headwaters — daemon not reachable` with the reason in the tooltip. The poll is **60 s**
  (`STATUS_POLL_MS`), one read at a time (concurrent `refresh()` calls join the in-flight promise),
  and **no retry loop** — the next tick is the retry.
- **D-507-6 — The MCP session is retried once, not forever.** A rejected or expired session is
  re-initialized exactly once and the call retried; a second rejection fails with a message naming
  the cause and saying that restarting the daemon clears it. Tests assert the call count, not just
  the message.

  package` (verified: it packaged), it only stops `npm publish`; removing it would be a licensing
  statement, not a packaging fix. `license` moved from `UNLICENSED` to `SEE LICENSE IN LICENSE` with
  a new extension-local `LICENSE` that restates the root placeholder (D1: nothing is granted) rather
  than loosening it. The root `LICENSE` was not touched.
- **Publisher identity is unverified.** `"publisher": "headwaters"` came from HDW-506 and is not
  proven to be a namespace this project owns on either registry. It is a placeholder until an owner
  claims it (FU-507-2).
- **`headwaters.refreshModels`'s title changed** from `Headwaters: Refresh Models` to `Refresh Models`
  with `category: Headwaters`, because the palette renders `category: title` and the old entry showed
  the prefix twice next to the seven new commands.
- **No manual click-through in the UI.** The `.vsix` was installed into the real VS Code and listed,
  and every command was executed in a real extension host, but nobody clicked the item or a palette
  entry with a mouse in this session; the manual checklist item is evidenced by the install commands
  above plus the extension-host runs.
- **No icon and no gallery banner.** The repository has no extension icon asset and this session must
  not generate brand art; the Marketplace tolerates a missing `icon`, so it is left out and recorded
