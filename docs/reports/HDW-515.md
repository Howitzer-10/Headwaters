## What the ticket asked for

Register two distinct products with two distinct endpoints — `opencode` (Console, account
authenticated) and `opencode-go` (the Go plan, static key) — with tiers grounded in evidence rather
than optimism, plus the correction of assumption **A-OC-3**, which HDW-514 used to defer OpenCode.

Both names are now catalog data. Neither is `free_cloud`, and the report says why below.

## Per slice

**Slice A — packet.** `headwaters_ticket_packets/HDW-515.md` in HDW-514's shape: Part 1 holds the
brief, the Cline observations as *observations*, the A-OC-3 correction, the facts verified for this
ticket and the limits; Part 2 is the normative slices with accept-when lines; Part 3 is the
per-provider verification protocol that has to run before any code depends on a new fact.

**Slice B — registry rows.** `opencode` and `opencode-go` are two rows in `providers`, each with its
own `base_url`, `models_endpoint`, `metadata_url`, `source_url` and `checked: 2026-11-03`. Both
declare `OPENCODE_API_KEY`, which the catalog previously rejected as a duplicate: `_cross_references`
no longer rejects a repeated `env_var`. `KeyStore` was already keyed by provider name, so a key
saved for `opencode` never answers for `opencode-go`, while a variable in the environment reaches
both — that is the observed reality and it is what the tests pin. `opencode` was also in
`RESERVED_PROVIDER_NAMES` (a name that could not be registered); it is removed from that set, with
the data-driven refusal taking its place.

**Slice C — tier truth.** Both rows are `paid`.
* `opencode` (Console): the listing is public and lists nine ids ending `-free` at cost 0, but the
  Console docs say free-tier chat models "are only available from within OpenCode; other clients
  receive HTTP 403, even with an API key". Customer list price is pay as you go. The `-free` ids are
  therefore dropped at discovery (`skip_id_pattern: "(?i)-free$"`) and refused if asked for by name.
* `opencode-go`: a subscription (Go, Go Plus, Go Teams). Beam Free and Iceman Contributor Free are
  included at $0 per call, but the plan is not free — the same reading HDW-514 applied to Hugging
  Face included credits.
The decisive keyed probe was **not run**: `OPENCODE_API_KEY` is not set in this environment.

**Slice D — tests.** `tests/test_hdw515_opencode.py` covers: both rows registered with their own
chat and listing URLs; the listing URL is not `base_url + models_path` (that path is a 404 on this
provider); the tiers are exactly `paid`; `opencode-go` resolves and `open-code`/`opencode go` are
refused; a stored key is per provider while one variable reaches both; `provider_name("OPENCODE_API_KEY")`
resolves to `opencode`; a `-free` Console id is refused with `provider_unsupported` while the same
slug on Go is not; and the OpenCode listing dialect is read into capabilities.

**Slice E — docs.** `docs/SDK_FACTS.md` gained eight rows (both chat bases, both listings and the
404, the 401 on a bogus bearer versus the anonymous 200, the listing shape, the free ids per product,
the Console 403 quote, the Go plan prices, and the "not verified: no key present" row).
`docs/ASSUMPTIONS.md` rewrites A-OC-3 and adds a dated row; `docs/PROVIDERS.md` has the two
`SUPPORTED` rows and the updated data recipe.

## A-OC-3, corrected

The old row said free models exist but "no machine-readable list endpoint found". That clause was
wrong: both products publish a listing (`/inference/v1/models`, `/inference/go/v1/models`) that
answers 200 anonymously and marks the free ids at cost 0. The 403 HDW-514 saw was not anonymity
either: it is the OpenCode client that gates those ids, and the docs say an API key does not change
it. So HDW-514's decision — do not offer the free ids — stands, for a partly different and now
stated reason, and the reachability of those ids from Headwaters with a real key remains unverified
rather than assumed either way.

## Packet errors

1. The brief calls A-OC-3 "wrong in substance: the free models are account-gated, not anonymous".
   The substance is narrower: they are *client*-gated, and the Console docs say a key does not open
   them. The 403 HDW-514 saw was the gate, not the absence of an account.
2. The brief expects "a single `curl` with `OPENCODE_API_KEY` (console base URL)" to answer the
   decisive question. It cannot: the documented answer is 403 for any non-OpenCode client. It also
   could not be attempted (no key). Recorded as FU-515-1 rather than answered.
3. The brief lists ten Console free models; the API lists nine (see FU-515-10).
4. The brief calls D18 binding in `docs/DECISIONS.md`; that file has no D18 on this branch
   (see FU-515-9).
5. The brief names the provider schema but not `catalog/catalog.schema.json`, which is generated
   from it: adding a field required regenerating that file (`python -m headwaters.core.catalog.loader
   --write catalog/catalog.schema.json`), so the diff carries an extra 13 lines nobody budgeted for.
