## Summary
Every gateway response now carries the routing decision in headers: `x-headwaters-model`,
`x-headwaters-tier`, `x-headwaters-scope` and `x-headwaters-reason`, plus `x-headwaters-below-floor`
with the first suggestion code (FU-123-2), `x-headwaters-verify` (`pending` until a streamed answer's
check runs, the gate's own outcome after it, so `unchecked` is never dressed as verified, FU-130-1)
and `x-headwaters-advice` when advice is configured. The only body addition is a `headwaters` object
on a stream's final chunk, because that is the first moment the post-hoc check has a result
(FU-130-2). Failover before the first token, the cold-load first-token timeout and the
`x-session-id`/hash session key already existed; they are now covered from the gateway side, and a
failure after the first token is one terminal error frame plus `[DONE]` that also drops the session
pin, exactly as a failed verification does (FU-134-3).

## Deviations
- The full suite and mypy were run from this worktree
  (`C:\Projects\copilot-worktrees\Headwaters\howitzer-10-expert-lamp`), not from
  `C:\Projects\Headwaters`, because the tree under test is the worktree (the main checkout is on a
  different branch); logs are written here and deleted before the commit. Same deviation as HDW-301.
- `x-headwaters-verify` is omitted when no check is due at all (`verify: off`, or an answer the
  policy did not require a gate for) rather than sent as `skipped`: an absent header keeps a client
  from reading a status that was never evaluated. A gate that ran but checked nothing is still
  reported `unchecked`, never `pass`.
- `x-headwaters-verify: pending` is only sent when the decision requires verification; a stream that
  needs no gate gets no header instead of a `pending` that could never resolve.
- The advice text is the same human-readable sentence in the header and in the chunk (one source,
  `headwaters/core/advice.py`); a machine-readable advice code is a follow-up.
- `UNCHECKED_NOTE` sits next to `BELOW_FLOOR_WARNING` in the advice header and inline note, so an
  unchecked below-floor answer reads as "below the floor" and "not verified" rather than as either
  alone (FU-130-1).
- Nothing else was needed for the cold-load first-token timeout or the hash session key: both were
  already implemented in `headwaters/core/executor/executor.py` (`_first_token_limit`) and
  `headwaters/core/router_session.py` (`session_key`); this ticket covers them with gateway tests
  instead of reimplementing them.
