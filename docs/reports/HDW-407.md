# HDW-407 - Beta 0.1 docs and the release gate

Status: Done. Beta 0.1 is **not** shippable: the gate reports `NOT READY` because all 11
owner steps are still unrecorded. That is the intended result of this ticket.
Commit: the ticket's commit on `howitzer-10-sturdy-winner`, message
`HDW-407: beta 0.1 docs and the release gate`. This report ships inside that commit, so it
cannot name its own hash; `git log -1` on the branch is authoritative.

## Summary

`headwaters release-gate` is the deliverable. It runs 13 machine checks over the checkout
(the required documents exist and say what the packet requires, the generated host pages
match the installer adapters and their templates, the catalog seed still validates and the
published feed does not drift past its `schema_version`, and the packaging payload is
present) and reads 11 owner steps out of `docs/release/evidence.json` (the two clean-machine
runs, Authenticode signing, the two butler uploads, the store copy review, the tester
registration, the open-source spot check, the beta go/no-go). Any failed check or any
unrecorded step makes the command exit 1 and print `NOT READY` with the number of each; a
malformed evidence file exits 2 with one clean message. `headwaters release-docs` renders
`docs/hosts/index.md` plus one page per host straight from the installer adapters and their
template file names, so a page cannot describe a file the installer does not write, and
`release-gate` fails when a committed page is stale.

Around the gate: the README grew a beta banner, install steps, a host table, the free list
with the ★ legend and a docs map; `docs/BETA.md` is the beta promise page; six troubleshooting
sections cover the failure modes the packet lists; `docs/PRIVACY.md` states what leaves the
machine (nothing) and what the dashboard binds to (loopback only); `docs/ITCH_STORE.md` is
the store page copy; `docs/RELEASE_EVIDENCE.md` documents the evidence schema the gate
enforces. `docs/DECISIONS.md` gained D15 (tester offer = free Pro during the beta) and
`docs/ASSUMPTIONS.md` gained one row.

## Tests

Added, 112 tests:

- `tests/test_release_docs.py` (27). Rendering every page, the sentinel paths, the file table
  matching `template_names`, `stale_pages` ignoring line-ending noise, `write_pages` writing
  only what is missing or stale and returning exactly those names, and the generated pages
  being byte-identical to what is committed.
- `tests/test_release_gate.py` (75). Every one of the 13 checks in both directions, the
  validator messages for all 11 owner steps (each out-of-range value asserted by its own
  message, so a passing run cannot hide a broken threshold), malformed evidence
  (`not JSON`, `version` 2, `steps` a list), and `render`/`as_dict` plus the exit code path
  for `READY`, `NOT READY` and evidence errors.
- `tests/test_cli_release.py` (10). `release-gate` and `release-docs` through
  `tests/cli_support.py`, including `--json`, the exit codes, `not_a_checkout`, and a
  `release-docs --write` run that makes a second `release-gate` pass.

Extended: none. No existing test needed to change behaviour for this ticket.

Side effects: every test that writes anything does so under `tmp_path` - documents, evidence
files, feed files, a fake checkout and the rendered pages. `checkout()` in the CLI tests
builds `pyproject.toml` and `headwaters/` inside `tmp_path`, so `main()` never sees the real
tree. The renderer tests assert that the committed pages are current by rendering in memory
and comparing, not by writing to `docs/`.

## Deviations

- `docs/DECISIONS.md` gained D15. The packet asks for a promise about testers; the code and
  the store page have no discount to offer, so the tester promise is free Pro access during
  the beta. The gate's `testers` step checks a positive count, not a price.
- The owner steps' `where` text points at sections that exist: `RELEASE_CHECKLIST.md` 0/1/2/3,
  `RELEASE_CHECKLIST_LINUX.md` 0/1/3, plus the new `## 5. The gate` in both files. No owner
  is sent to a section number that the checklists do not have.
- `release_docs.write_pages` writes only pages that are missing or stale and returns exactly
  those names, so `release-docs` can be run in CI and its exit code means something. A fresh
  render of every page is byte-identical to the committed files, and `release-gate` fails on
  drift.
- `docs/ITCH_STORE.md` tells Linux users to unzip and run `install.sh`: the Linux payload
  ships that script and no `itch.toml`, so the page does not repeat the Windows
  "the itch app launches the installer" wording.
- A real bug was fixed while writing the tests: `release_gate.py` raised an undefined
  `_EvidenceError`, so malformed evidence would have produced a `NameError` traceback instead
  of the documented exit 2.
- `tests/test_release_gate.py` no longer contains the literal butler script name, because
  `tests/test_packaging_artifacts.py` forbids it under `tests/`; the name is assembled at
  runtime, which is what that guard's own file does.
- No `docs/SDK_FACTS.md` rows were added or re-verified: nothing in this ticket depended on
  SDK or tooling behaviour beyond what is already recorded, and no SDK version changed.
