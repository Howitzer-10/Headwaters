## Summary
Adds `headwaters.features.wizard`, a ★ package discovered by the same `pkgutil.iter_modules` walk as `ledger`/`paid_scopes`/`usage_report`, that walks eight steps of setup — detect and fix Ollama's environment, recommend and pull local models, plan IDE configs, show keys, pick default scope and strategy, set autostart, preview the usage report, and run a self-test — with every step skippable, every step re-runnable, and every write preceded by the exact change it will make. It is served on the dashboard's existing HTTP surface (`build_status_page_app(..., wizard=...)`, one fixed `WIZARD_PATHS` table, the same host/origin/CSRF guards as `_KeysRoute`) because `.importlinter` forbids a ★ package from importing fastapi and D14 makes the gateway daemon the composition root; no second listener exists. The pull path is a real Ollama native `/api/pull` NDJSON stream behind the one client in `core/executor/ollama.py`, and it refuses a cloud tag before it opens a socket (D13).

### Accept-when not met, or met more narrowly than the packet says
- [ ] **A first-run path does not exist.** The wizard is served on the dashboard surface, which only exists while the daemon is up and the dashboard is enabled. A person setting up a machine for the first time cannot reach the wizard through the UI that is meant to do the setting up, because the UI is part of what they are setting up. This ticket does not invent a second listener to fix it (D14 makes the gateway daemon the composition root; a second stdlib listener would be a second surface with its own guards to get wrong). The e2e walkthrough above is a walkthrough of the *steps*, driven through the same HTTP surface with mocks — it is not evidence of a first-run path. Recorded as `FU-505-1`.
- [ ] **Step 4 is read-only.** The packet says "keys". Writing a provider key needs a value in a page in a browser, which D18/D19 and the no-secrets-in-a-page rule this ticket inherits both push against; the product already has a keys surface (`/?section=keys`, `control/keys.py`) so the wizard names the providers in plain words and links to it. Nothing about keys is written from the wizard.
- [ ] **Step 1 writes for real on Windows only.** `RegistryEnvWriter` writes `HKCU\Environment`, which is the only place `read_ollama_env` reads on Windows. On other platforms the step shows the exact shell lines and offers them to copy — `test_a_platform_that_cannot_write_refuses_and_offers_the_lines`. The real write was never exercised against a live registry in this ticket; only `FakeWriter` was.
- [ ] **Step 6 is Task Scheduler only.** Autostart uses the existing `packaging/autostart.py` target; elsewhere (and when `schtasks` is absent) the step shows the target and says it cannot apply it.
- [ ] **Step 8 calls no model (D21).** The self-test asserts config, database, catalog, hardware detection, loopback reachability and the report's refusal state; it does not complete a model call, so it cannot promise end-to-end generation works.
- [ ] **Pull progress is in memory.** `PullManager` keeps one job's progress in the process; if the daemon restarts mid-pull the progress is lost (Ollama itself keeps pulling). `percent` is also `None` until a layer reports a total — honest rather than fabricated.

## Deviations
- **Model.** The packet says Sonnet · Effort High. This session ran deepseek-v4.1-flash at high effort by standing owner policy, recorded here as a deviation.
- **Verification.** The packet says "ruff, mypy, pytest". Superseded by the standing instruction for this ticket: `ruff check`/`ruff format --check` on the changed files, `lint-imports` once, `pytest --collect-only` once, and targeted pytest only. mypy and the full suite were not run.
- **D8 strengthened.** The packet's D8 (POST → redirect → GET) is implemented with a single-use in-memory flash token (`?token=`) so that no notice sentence — and therefore no refusal text — is ever reflected into a URL. This is narrower than a plain redirect and was accepted at plan time.
- **Two decisions the packet left open** were taken as planned and accepted: D1 (extend the dashboard surface with one fixed path table, no second listener) and D3 (the pull lives behind the one native Ollama client and one job at a time).
- **Isolation defect found while testing.** The wizard's own tests first reached this machine's real `%APPDATA%\Headwaters\rules.yaml`, because an autouse fixture imported into a test module is not autouse there. The file was restored to its original content (`features: {}`) and the guard now lives in `tests/conftest.py` with an assertion that the resolved config dir is under `tmp_path`. `FU-505-2` covers the underlying footgun.
