## Summary

The status page is no longer read-only. It gains a **Keys** section built from `KeyStore.providers()`
(D18), one expandable `<details>` per provider, one row per alias with its source, a prefix-free mask,
its last test, and Replace/Test/Remove forms — plus **exactly three writes**, all on the dashboard
app the daemon already binds to `127.0.0.1`: `POST /keys/set`, `POST /keys/remove`,
`POST /keys/test`.

The writes are guarded by a port-aware `Host` check, an `Origin`/`Referer` check, a form-only body
cap and a per-start CSRF token (all 403/415/413, per the packet), then a person-actionable refusal
comes back as the page at 400 with a secret-free sentence. A successful write is a `303` to
`/?section=keys#keys-<provider>`. Test results are persisted for the first time (migration 6,
`key_tests`), written by the same `check_and_record` path the CLI now uses, so `headwaters keys test`
and the dashboard cannot disagree.

Nothing else on the page changes anything: no live decisions, no savings, no model fit, no
verification catches, no feedback, no scope or feature controls (see Follow-ups).

## Accept-when check — the ten write-API lines

1. **Loopback port only.** The writes are routes on the dashboard app the daemon already serves;
   `serve()` passes `port=self.ports.dashboard`, never `rules.dashboard.port` (FU-201-6).
   *Proven by* `test_a_write_against_another_port_on_this_host_is_refused`.
2. **CSRF token, one per daemon start, memory only.** `Daemon.dashboard_csrf` is
   `secrets.token_urlsafe(32)` from `field(default_factory=...)`; `status()` builds its dict
   explicitly, so it is not in `daemon.json` or a log line. A missing or wrong token is 403 with
   nothing written (`hmac.compare_digest`; an empty configured token refuses everything).
   *Proven by* `test_a_write_needs_the_page_token`.
3. **`Host` loopback *and* on the dashboard port, else 403**, without touching the read path's 421.
   `is_dashboard_authority` checks the hostname *and* `urlsplit("//"+host).port`; `LoopbackOnlyApp`
   skips its read guard only for the three write paths. *Proven by*
   `test_a_write_from_a_foreign_host_is_refused_with_403`,
   `test_a_write_against_another_port_on_this_host_is_refused`, and the unchanged read-path
   assertions (`tests/test_status_page.py::test_the_page_is_served_read_only_and_refuses_a_foreign_host`
   at 421, `tests/test_gateway_ports.py` at 421 for a rebound address).
4. **`Origin` preferred, `Referer` fallback, both allowed absent.** `is_dashboard_origin` requires
   scheme `http`, a loopback host and the exact port. *Proven by*
   `test_a_write_from_another_origin_is_refused_even_with_the_token` (three foreign origins plus
   `null`, then the dashboard's own `Origin` and a same-site `Referer` both 303).
5. **Form-encoded bodies only, capped.** Anything but
   `application/x-www-form-urlencoded` is 415; the body is read with a running cap and anything over
   8 KiB is 413. *Proven by* `test_a_write_only_accepts_a_small_form`.
6. **No CORS headers, no preflight route, `OPTIONS` 405.** The app adds no CORS middleware and no
   `OPTIONS` route, so Starlette answers 405 for the path. *Proven by*
   `test_a_get_to_a_write_path_is_not_allowed` (GET, PUT and OPTIONS).
7. **The secret travels in the body only.** It is read from the form and never echoed; the redirect
   target carries the provider name only. *Proven by* the `SECRET not in ...` assertions in every
   write test.
8. **POST-redirect-GET on success, a real status on failure.** Success is `303` to
   `/?section=keys#keys-<provider>`; a `KeyStoreError` re-renders the page at 400 with
   `<p class="error">`, any other exception at 500. *Proven by*
   `test_saving_a_key_shows_it_masked_and_never_its_prefix`,
   `test_removing_a_key_takes_it_off_the_page`, `test_a_refused_write_comes_back_as_the_page_with_a_sentence`.
9. **Failures reuse the existing redaction.** `KeyStoreError` text carries no value and no
   environment-variable name; every refusal asserts the secret is absent from the body.
10. **Only GET and POST are routed on these paths.** GET is the page, POST the three actions, so any
    other method is 405. *Proven by* `test_a_get_to_a_write_path_is_not_allowed`.

## Accept-when check — the section itself

- **One row per alias, from the key store.** Generated from `store.providers()` and `store.entries()`
  in `_key_groups`; the groups test asserts the page's order equals `store.providers()`, including
  the keyless `ollama` group with no keys.
- **Grouped and expandable.** One `<details id="keys-<provider>">` per provider whose `<summary>`
  carries name, tier words, state and last test.
- **Add-key form at the top**, alias defaulting to the provider name, a `<select>` of registry names,
  the CSRF field, a `type="password"` key field.
- **The provider list grows with no code change.** Nothing in the page hard-codes a name; the test
  compares the rendered order with `KeyStore.providers()`.
- **Honest status, never a green tick for an absent key.** State words are `credential store`,
  `key from the environment`, `no key saved`, plus the "No key is saved for X…" note; a provider with
  no key also drives the paid-scope note. *Proven by*
  `test_the_page_says_why_paid_scope_is_unavailable_until_a_paid_key_exists`.
- **Remove tells the truth.** Removing an environment-only key does not raise: the key stays and the
  page says it comes back from the environment. *Proven by*
  `test_a_key_from_the_environment_cannot_be_removed_here_and_the_page_says_so`.
- **Deep links.** `?section=keys` renders the Keys section first, server-side, no second route.
  *Proven by* the section-order test.
- **Never an environment-variable name.** The page is built from a store with `HF_TOKEN`-style
  environment mappings and the rendered HTML is asserted to contain none of them.
- **Never a key prefix.** The packet supersedes `KeyInfo.masked` here: `tail_mask` renders four
  stars and the last four characters, and the tests assert no prefix of the secret (`SECRET[:8]`,
  `SECRET[:-4]`, `SECRET`) appears. `mask()` and the CLI are unchanged.
- **Updated, not deleted, read-only assertions.** `tests/test_status_page.py` keeps its read-path
  tests (including "no editing controls without a key backend") and the docstring was rewritten.

## Assumptions

The full row is in `docs/ASSUMPTIONS.md` (2026-11-12, HDW-503). In short: the page is still
read-mostly and only the Keys section writes; the write guard is deliberately stricter than the read
guard's 421; the CSRF token is memory-only; test results live in `key_tests` with no pruning (one row
per alias, so it is bounded); `build_status_page_app` was widened on purpose; no new external SDK
fact was needed, so `docs/SDK_FACTS.md` carries no HDW-503 row.

## Deviations

- **`tail_mask` instead of `KeyInfo.masked`.** The packet's own "never a prefix" rule supersedes the
  "`mask()` output" wording in the row definition and the set-test; `mask()` is untouched.
- **`check_and_record`, not `test_and_record`.** Ruff's pytest-style rules treat a module-level
  `test_*` function in `headwaters/control/` as a test and demand it take no default arguments.
  Renaming was cheaper and clearer than a per-file ignore.
- **`kilo`.** This branch's registry carries a keyless `kilo` row from HDW-514's catalog work, which
  is not in the packet's canonical name list. The page shows it because D18 says read
  `providers()`; nothing in this ticket adds or removes a provider, and the D18 row in
  `docs/DECISIONS.md` says the registry is the list and notes the extra row (FU-503-2).
- **D16/D17 are absent from the decision table on this branch** (D16 exists only as a detail
  section, D17 is claimed by two unmerged branches). D18 was added with a numbering note; D16/D17
  were not invented here.
- **The daemon's `dashboard_csrf` is a dataclass field.** The alternative — a module global or a
  `serve()` local — would have hidden the token from `dashboard_page`, which needs it.
