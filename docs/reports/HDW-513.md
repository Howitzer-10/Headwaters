# HDW-513 - Cascades remember what failed and reach a healthy tier

_Ticket: `headwaters_ticket_packets/HDW-513.md`. Branch: `howitzer-10-hdw-513-cascade-fallback`._

## What was wrong

A Cline user set the model to `headwaters/auto`, sent one prompt (`Just testing model, so reply "Hello, Jim"`)
and waited 21 minutes for `The run failed: Every allowed attempt failed.` The prompt was trivial; the
tools payload made it a 14,680-token code request, and the routing layer answered it with four
attempts at the same dead free model.

Two defects, both in the retry loop rather than in any model:

1. **No per-request failure memory.** `Router._recover` re-decided after every failure, but nothing
   told the next decision that a model had just failed. Every attempt re-selected the same top
   candidate (`google/gemma-4-26b-a4b-it:free`) and re-failed through the same prefix of the
   alternative list. The `alternatives` array grew, so a record existed - nobody consulted it.
2. **Tier ordering starved the local tier.** The ladder was all `free_cloud` entries first and all
   local entries last. With `router.max_attempts: 4` and a dead free tier the request could not reach
   a local model even though the same gateway had answered with `qwen3-vl:8b-instruct` 90 seconds
   earlier (decision 8).

Both surfaced to the user as one opaque string that hid the real cause (no credential at all).

## Evidence reproduced

Replayed from `%LOCALAPPDATA%\Headwaters\headwaters.db` (decisions 9-12, session
`h:152782041447a0be2607458a9671b0ff`, about 50 s apart): identical requirements each time
(`est_tokens` 14680, `hard.tools` true, `soft.task` `code`, complexity 3, floor 100.0), the same
`chosen` model all four times, and the same four `provider_error` reasons in front of a still-growing
alternative list that ended with 13 local models.

Re-verified live in this session:

```
$ Invoke-WebRequest -Method Post https://openrouter.ai/api/v1/chat/completions -Body '{"model":"google/gemma-4-26b-a4b-it:free",...}'
status 401
{"error":{"message":"No cookie auth credentials found","code":401}}

$ uv run --frozen headwaters keys list
| anthropic  | anthropic  | not set | - |
| openai     | openai     | not set | - |
| openrouter | openrouter | not set | - |
```

So every attempt was doomed to the same 401: the failure was a missing credential, not model quality,
and the router had no way to say so. Both facts are now rows in `docs/SDK_FACTS.md`.

## What changed

Binding decision: **D17** in `docs/DECISIONS.md`.

### Slice A - per-request failure memory

- New `headwaters/core/router_failures.py`:

  - `FailureRecord(model, tier, provider, code, status)`,
  - `FailureMemory` - `record(...)`, `excluded`, `records`, `exclude_provider(...)`, `skip_line(...)`,
  - `failure_class(...)` - `401`/`403` becomes `auth_missing_key` when the (cached) key store holds no
    secret for that provider, `auth` when one is present; plus `provider_error`, `rate_limit`,
    `overload`, `context`, `timeout`, `cancelled`.
- `headwaters/core/router_run.py`: `RouteRun.failures: FailureMemory` (the old `excluded` set is now a
  property over it), discarded with the run. This is per-request state, **not** a cooldown: it never
  writes a wall, so HDW-511's walls/backoff are untouched and the model is free to serve the next
  request.
- `headwaters/core/router.py#_recover`: records the failure before the next decision, keeps
  retry-class walls (`rate_limit`, `overload`) for their own retry, and adds one visible line:
  `attempt 2 of 4: skipping 4 models that already failed in this request` (the count is failed
  models, not provider-skips).
- A `context` failure only excludes the model for this request, because `quotas.record_wall` returns
  `none` for a `context` wall - a model that would work on a smaller payload is not punished.

### Slice B - tier fairness and the local fallback

- `headwaters/core/policy/ladder.py`: new public `interleave_tiers(entries, tried)`, called by
  `build_ladder`. It groups the already-built, already-ranked ladder entries into one queue per tier
  in first-appearance order and emits round-robin, **starting after the tier attempted last**
  (`tried`). One tier in scope returns the input unchanged, so single-tier decisions are byte-for-byte
  what they were.
- `headwaters/core/policy/types.py`: `PolicyRequest.tier_attempts` carries the attempted tiers;
  `headwaters/core/router.py#_redecide` fills it from `run.attempts`.
- `headwaters/core/policy/decide.py`: reason line `tier fairness: free_cloud, local interleaved, one
  attempt each before any repeat`.
- The carry is what makes the guarantee hold. A stateless interleave cannot do it: after excluding the
  failed model, the same tier is again at the head of its own queue. Rotating from the last attempted
  tier yields `free, local, free, local` and no tier can take a second attempt while another tier is
  waiting. `max_attempts` still wins; tiers that scope, locks or privacy rules exclude never enter the
  ladder, so fairness cannot widen the scope.

### Slice C - the honest terminal error

- `router_failures.terminal_message(...)`: `All N allowed attempts failed.`, then one line per attempt
  (model, tier, provider, failure class, short reason), capped at four attempt lines; the missing-key
  fix command when a credential is the cause (`headwaters keys set openrouter`); and a line naming a
  usable tier that was never tried (`Local models were available in this scope but never tried`).
  Bounded to a handful of lines so it stays readable in a chat host.
- `router_failures.redact(...)` masks credential-shaped substrings before any echoed text
  (`sk-or-v1-...`, `api_key=...`, `Bearer ...`, `Authorization:`). Masks are bare `****`, because a
  mask that keeps the prefix (`sk-****`) is re-matched by the generic `sk-` rule and turns into
  `sk-********`.
- `headwaters/core/router.py#_failure_message`/`_untried_tiers` build the message for both
  `attempts_exhausted` and `no_route_left`; strict-pin and scope-violation messages are redacted too.
- `headwaters/core/executor/executor.py#key_present(provider)` reads the cached `_api_key_for` - no
  network call on the hot path - so a cloud provider with no key is skipped for the whole request in
  one reason line (`no key for openrouter: skipping its 2 models`) instead of costing an attempt per
  model. Local providers are never treated as unauthenticated.

## Behaviour verified

`tests/test_router_failures.py` (9 tests) covers all six required cases: same-model re-selection
prevented; a dead tier cannot consume all attempts; local reached after a dead free tier; the terminal
message naming the missing key and the fix command; credential redaction (including a token inside a
model id); an unauthenticated cloud provider recorded as `auth_missing_key` with its provider skipped.

The live scenario, reproduced against a rig with no key store, four `:free` models and a healthy local
tier, reproduced from the run's own state DB:

```
== dead free tier, healthy local behind it (max_attempts 2) ==
attempts: [('or/free-a:free', 'free_cloud', 'auth_missing_key'), ('qwen3-vl:8b', 'local', 'ok')] | chosen: qwen3-vl:8b
-- decision 1: chosen qwen3-vl:8b
   reason: scope tiers: free_cloud, local
   reason: default scope: auto
   reason: paid tiers excluded: the paid-scopes feature is not enabled
   reason: floor 80 for code
   reason: cheap: qwen3-vl:8b score 78.0, floor 80
   reason: no key for openrouter: skipping its 2 models
   reason: attempt 2 of 2: skipping 1 model that already failed in this request
   reason: or/free-a:free: auth_missing_key, cascading

== four attempts, every model fails ==
All 4 allowed attempts failed.
- attempt 1: or/free-a:free (free_cloud, openrouter) - authentication: OpenRouter rejected the credential (401)
- attempt 2: qwen3-vl:8b (local, qwen3-vl:8b) - provider_error (HTTP 500)
- attempt 3: or/free-b:free (free_cloud, openrouter) - authentication: OpenRouter rejected the credential (401)
- attempt 4: gemma4:12b (local, gemma4:12b) - provider_error (HTTP 500)
OpenRouter rejected the credential (401). Save a replacement with: headwaters keys set openrouter
models tried: ['or/free-a:free', 'qwen3-vl:8b', 'or/free-b:free', 'gemma4:12b']
```

Read against the ticket: the same model is never attempted twice (attempt 3 is the *other* free
model), the two tiers alternate, local is reached after the free tier dies, and the terminal text names
the class, the provider and the command that fixes it instead of `Every allowed attempt failed.`

Existing suites are unchanged: the router tests, the walls/escalation/stickiness tests and the three
policy golden suites pass without edits, which is the evidence that the interleave keeps `ladder[0]`
and rung precedence.

## Assumptions and deviations

- Work was done in the session worktree `C:\Projects\copilot-worktrees\Headwaters\howitzer-10-urban-goggles`
  rather than the main checkout, as the session requires.
- The live 401 was re-verified from this session (keyless `POST`, plus `headwaters keys list`); no key
  was added, no provider configured, nothing was sent to a paid endpoint.
- The state DB replay showed *different* models in `alternatives` across attempts 9-12, so the live
  defect is not a literal ping-pong between two models: it is that nothing consulted that growing
  record, so the same top choice was re-attempted and the free tier was re-entered each time. Slice A
  is therefore implemented as exclusion by identity plus failure classes plus the provider fast-fail,
  which is what converts "record exists" into "record is consulted".
- No SDK version changed, so no SDK_FACTS row was re-verified; two new rows were added for the
  keyless OpenRouter 401 and for `headwaters keys list`.
- `docs/DECISIONS.md` gained D17 (binding tier fairness and per-request memory rule).

## Deferred

- The 14,680-token tools payload and tool/schema pruning: out of scope (that is what turned a trivial
  prompt into a code request).
- The HDW-511 composition error, and any change to the global walls/backoff: deliberately untouched;
  the per-request memory is separate by design.
- Enabling the paid-scopes feature, adding providers or keys, changing Cline's configuration: not this
  ticket.
- A per-model (rather than per-provider) authentication fast-fail: D17's revisit condition; no
  provider has per-model credentials today.
- Replaying the original Cline session end to end needs a live key or Ollama plus Cline, which this
  session does not have; the behaviour was verified at the router boundary with the same shapes.
