## Summary
A capability was taken from what a provider advertises, so the router offered tool requests to
`qwen2.5-coder:14b`, which answers a tool call as JSON text: Cline then showed
`{"name": "skills", "arguments": {"skill": "test"}}` instead of an answer. `tools_ok` is now recorded
from an observation (a bounded probe that requires a structured `tool_calls` entry naming the offered
tool), `models.overrides` finally reaches routing so the owner can correct any field by hand, the
`pull_model` hint stops recommending the model it just chose, and the gateway gained an opt-in,
configurable answer footer that names the model that answered and the cost, with the plain-text
default off so no client sees new bytes.

## What was wrong

1. **The capability came from the advertisement.** `headwaters/core/state_models.py` wrote `tools_ok`
   from what the provider's model list claimed. `qwen2.5-coder:14b` advertises
   `['completion', 'tools', 'insert']` on Ollama 0.40.13 and returns `tool_calls: null` with
   `content='{"name": "headwaters_status", "arguments": {}}'`. The router had no way to know.
2. **The correction path did not exist.** `ModelOverride.tools_ok` was declared and validated, and
   nothing read `ModelsRules.overrides`: no code path could change a model's tier, scores, `tools_ok`,
   `json_ok` or `ctx`.
3. **The hint contradicted the choice.** `pull_model` was built from the GPU profile's recommended
   model, so it said "pull the model it just chose".

## Slice A — verify tool capability behaviourally

`models verify-tools` probes one model or every model in the tier; `models refresh --verify-tools`
does it after a refresh, and `models.tool_probe.on_refresh` is off by default, so a refresh alone
never loads a model. The probe offers one synthetic tool (`headwaters_probe`), asks for it once, and
classifies the channel, not the wording: `structured` (the call in `tool_calls` naming the offered
tool, empty content) is the only pass. `call_as_text` is the defect, `wrong_tool`, `text_answer` and
`empty` are failures. `error:…` (unreachable, refused by the lock, cut off at the token cap) and
`skipped:…` (disabled, over the `max_models` cap, verified within `retry_after_s`) record nothing, so a
model that could not be verified keeps its previous value and never silently becomes `tools_ok`.
The probe never runs in a request path: it is an explicit command, decided in the packet, because it
loads a model. It is idempotent (one row per model and capability) and bounded by the command's own
executor, which enforces the private lock, airplane mode and scope before any call.

## Slice B — overrides that actually apply

`apply_overrides` runs after the catalog and scoring and before the session pin, exactly as the
`ModelOverride` docstring promised, and covers `tier`, `scores`, `tools_ok`, `json_ok` and `ctx`.
`models list` shows the stored state; routing reads the same override index through the rules the
watcher already refreshes, so an edited `rules.yaml` takes effect without a daemon restart. A bad
override fails `rules.yaml` with a clear error instead of being ignored.

## Slice C — an honest hint

`pull_hint` now scans past every installed model, and the `pull_model` suggestion names a model only
when one remains that is not installed; when the shortfall is a tools-capacity shortfall the text says
that instead of recommending a bigger model. Never recommends the model it just chose: the packet's
case (`pick --tools --tokens 15000 --scope local`) is covered by `tests/test_hdw512_pull_hint.py`.

## Slice D — the footer

`gateway.footer` is a rules section with `enabled` (default `false`) and `fields`, and each field is
an enum member with its own formatter, so a new field is one enum entry and one formatter. Supported:
`model`, `tier`, `tokens`, `cost`, `latency`. The line is `Headwaters: model=… tier=… tokens=P+C
cost=… latency=… ms`, in the configured order, on one line after a blank line. Cost reads `free` for a
local answer and for a zero cost, `unknown` when the catalog has no price, else `$0.001234`. The data
comes from `headwaters_meta`, the same dict the stream's `headwaters` chunk already carries, so cost is
priced once in the router. Anthropic's route carries it inside the open text block and skips it for a
`tool_use` answer, which cannot take text without changing the block structure.

## Deviations
- The probe's token cap is 256 rather than 64. At 64 a thinking model (`qwen3:8b`) spent the whole cap
  reasoning and looked like a refusal; a truncated answer is now `error:truncated` and records nothing,
  and the real run above shows it passing with room. This is stricter, not looser: it removes a false
  negative without ever inventing a pass.
- `docs/SDK_FACTS.md` gained an Ollama HTTP API row (the one new SDK-adjacent fact this ticket needed);
  the probe budget was not otherwise used.
