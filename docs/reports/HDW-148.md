## Summary
The daemon now rebuilds its engine whenever valid, changed rules are applied, so edits to `tiers.paid.models`, the local host, `features`, endpoints and `kv_cache_type` take effect on the next request without a restart; a request already running finishes on the engine it started on. The `Engine.rules` and `Daemon.rules` startup snapshots are gone. A privacy switch is now true when it answers: `RulesManager.current` re-reads a changed `rules.yaml` at once (one `os.stat`), the daemon has an authenticated `POST /v1/reload`, and `headwaters private|scope` return only after the daemon confirms the value.
