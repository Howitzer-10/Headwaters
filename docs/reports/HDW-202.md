## Summary
Added the stdio MCP shim, `headwaters-mcp` (also `python -m headwaters.mcp`). It is a thin low-level MCP server that forwards `tools/list` and `tools/call` to the shared daemon's `/mcp` endpoint with the per-user token, and starts the daemon when it is not running. Stdout carries only JSON-RPC (`guard_stdout` plus the SDK's fd-1 claim), everything is UTF-8, and `headwaters mcp-path` prints the absolute launcher and an `mcpServers` snippet for host configs. The `mcp` contract is shown to bite in the real tree. The shim has no tools of its own: they come from the daemon, which registers none until HDW-203.

## Deviations
- Added `CREATE_BREAKAWAY_FROM_JOB` to the daemon spawn in `core/daemon_control.py` (HDW-201 code). The ticket did not ask for it, but the SDK's own stdio client runs the shim in a kill-on-close Job Object, so a daemon started by a shim was killed when the client closed. The change is small and falls back to the old behaviour. It did not fully fix this: see FU-202-1.
- Fixed the leaked-process bug in the HDW-201 live tests (see Files changed) although it is outside this ticket, with the owner's permission; it is therefore not a follow-up.
- The shim is split across `shim.py` and `link.py` (not one file) to stay within editing limits; the repo layout names `shim` and `server`, and no separate `server.py` is needed.
- No conflicts with D7 to D14 found. D8 holds: all SDK imports stay in `headwaters/mcp/`; `mcp_launch.py` in core only builds paths.
