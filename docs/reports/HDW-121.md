## Summary
Ollama cloud-proxied models (`gpt-oss:120b-cloud`, any `remote_model`/`remote_host` entry) are no longer discovered as `local`. Per D13 discovery drops them, and `enforce_scope`, the executor, `OllamaBackend` and the layer-3 classifier each refuse them (defence in depth). The name patterns are catalog data (`ollama_remote_patterns`), and A-OLL-9 is now verified against a live probe and the current Ollama docs.

## Assumptions
- A-OLL-9 (verified 2026-10-31): `/api/tags` marks a cloud model with `remote_model`, `remote_host` and a `-cloud` name; `/api/show` carries no remote fields; disabling is `OLLAMA_NO_CLOUD=1` or `disable_ollama_cloud`. Replaces the reviewer's earlier unverified A-OLL-9 row.

## Deviations
- D13 overrides the packet: the packet says "`tier=free_cloud`/`paid` per catalog, or drops them" and "`retains_data=true`". Only "drops them" is built; no `free_cloud`/`paid` classification and no `retains_data` marking.
- "The layer-3 classifier refuses one too": it returns `None` for a remote model (layer 1 result stands, the analyzer chain's normal failure path) instead of raising, because a classifier error must never break routing.
- The `doctor` hint is not built (see FU-121-1): the ticket line depends on HDW-402, which does not exist yet.
- `/api/show` has no remote fields on Ollama 0.40.13, so the packet's "remote fields in `/api/show`" is only honoured defensively.
