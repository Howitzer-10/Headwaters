## Summary
The daemon now serves an OpenAI-compatible gateway on its own loopback port: `/v1/models` lists the
four core picker models (plus `quality`/`duck` when `picker.show_extras` is on), and
`/v1/chat/completions` takes streaming and non-streaming requests through `Router.handle`, with
OpenAI-shaped bodies, SSE chunks, usage and errors. FU-201-6 is closed by binding the gateway port
with `netports.bind_first_free` and serving the app on that socket, so `daemon.json` names the port
that is really listening. FU-135-3 is closed by appending a `data:` URL instruction to any refusal
caused by a remote image URL.

## Deviations
- Starlette, not FastAPI, for the new app: the daemon already serves Starlette (`headwaters/gateway`)
  and `.importlinter` allows it there; FastAPI would add a dependency for no route we need.
- `openai` is a **dev** dependency only, used by the tests as the real client; nothing at runtime
  imports it, so the pinning rule for LiteLLM never applies (LiteLLM is not used at all).
- `pick_ports` now returns `(api_sock, gateway_sock, DaemonPorts)`; `daemon/runner.py` and
  `tests/rebuild_support.py` are the only callers and both use keywords.
- The full suite was run from this worktree (`C:\Projects\copilot-worktrees\Headwaters\howitzer-10-super-barnacle`),
  not from `C:\Projects\Headwaters`, because the tree under test is the worktree; logs are written
  here and deleted before the commit.
- The dashboard port is still only probed (FU-201-6 named the gateway); binding it is HDW-401.
