## Summary
Three guards close the gaps FU-121-4, FU-126-3 and FU-135-2. `CandidateBuilder` re-checks every
`local` row against the catalog's cloud-proxied name patterns, so a stale `local` row for
`gpt-oss:120b-cloud` never becomes a candidate; `discover_features` skips `_`-prefixed packages
unless a caller asks; and a request carrying a remote image URL drops local candidates in the hard
filter with the reason `image_url_not_local`, instead of spending an attempt on a refusal.

## Deviations
- The stale-row failure mode in local scope changed from `RouteFailed` code `local_scope_violation` to `ScopeError` code `local_unavailable` with the doctor pull hint, and the test was renamed to match. Once the builder drops the row there is no local candidate at all, so `local_usable` is false and scope resolution reports the honest "only local models are allowed here, but none is available" error before routing. The executor refusal is unchanged and still covered by tests/test_ollama_remote_exec.py.
- The packet asks the builder to check "name and fields". `ModelRow` has no remote-model columns and the catalog `ModelEntry` has no remote fields, so the check uses the row id plus the entry's aliases; `has_remote_fields` is not consulted here (FU-153-2).
- `include_private` is a keyword-only opt-in rather than a separate function, so production callers (`engine`, `cli/runtime`, `cli/cmd_features`) keep their signature and behaviour.
- The golden scenario runner gained one keyword (`remote_image`) so the new cases fit the existing table instead of a second harness.
