# HDW-516 - Cloud-first descending order

_Ticket: `headwaters_ticket_packets/HDW-516.md`. Branch: `howitzer-10-hdw-516-cloud-first-ordering`,
stacked on HDW-513's `0ffe95a` (`howitzer-10-hdw-513-cascade-fallback`)._

## Summary

`router.tier_order` now selects how the fallback ladder is ordered. The default, `interleave`, is
HDW-513's round-robin and is byte-identical (every pre-existing order test passes unmodified).
`descend` exhausts one tier before the next, walking `paid -> openrouter_auto -> free_cloud -> local`
or the exact reverse per `router.tier_direction`. The order is a rules setting only: `decide()`
overrides whatever the caller put on the request, so a request cannot widen or narrow its own scope
by asking for an order. The surfaces (status page, `headwaters status`, `headwaters pick`, MCP
`scope_info` and the `scope` tool's note) read one registry, `TIER_ORDERS`/`TIER_DIRECTIONS` in
`headwaters/core/rules.py`, instead of retyping the names.

## Deviations

- **D19 is not in `docs/DECISIONS.md`.** The brief named D7 and D19 as binding; the file's last
  entry is D15 (HDW-513 added D17 - see its report - so the numbering in the tree is ahead of the
  file in places). Nothing in the ticket needed wording that D7 and the interleave rule did not
  already settle, so no decision entry was invented. FU-516-3.
- **The packet's test names were not used verbatim.** Several of its names presuppose fixtures that
  do not exist (`test_descend_cannot_clear_below_floor_or_verify_required` reads as if `descend`
  could clear them) and Part 3 truncated after test 5 in the copy available here. The mapping above
  is one-to-one with the packet's intent; each behaviour is covered by a named test.
- **`unavailable_exhausted` does not exist.** Packet test 8 expects that rejected reason; the real
  code emits `unavailable_cooldown` for a walled model (`filters.py` `reason` codes). The test
  asserts the `unavailable_` family instead of hard-coding a code that is not there.
- **A paid candidate must be a primary to enter the ladder at all.** `build_ladder` builds `paid`
  from `is_primary` candidates plus `openrouter/auto`; a plain paid catalog entry is never a
  fallback under any order. That is pre-existing behaviour (not changed here), and it is why the
  paid-tier fixtures are marked primary. FU-516-4.
- **`interleave` ignores `tier_direction`.** Setting `local_first` with `interleave` is validated and
  kept in the rules (and printed as bare `interleave`), but changes nothing; that is what packet test
  13 asks for, and it is the only reading that keeps the default path byte-identical.
- **The order is read from the rules, not the request.** `PolicyRequest` got the two fields so the
  preference survives `_redecide`, but `decide()` overwrites them from `ctx.rules` unconditionally.
  A caller cannot pick an order per request; only the user's `rules.yaml` can.
- Work happened in the session worktree `howitzer-10-solid-dollop`, not the main checkout. No push,
  no PR. Nothing was sent to any provider: no network call is made by any changed path.
