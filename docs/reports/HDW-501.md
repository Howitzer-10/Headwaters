## Summary

`headwaters/features/ledger/` is now a ★ module that reads the `decisions` and `outcomes` rows the
router already keeps and adds the one number they do not carry: what a reference model would have
charged for the same tokens, priced at a dated rate from the active catalog. It is served to
`headwaters_status`, the status page and the new `headwaters savings` command only through the
plugin registry, so core never names the feature and both keep answering with the folder deleted or
`features: {ledger: false}`. Every figure is labelled an estimate of what another model *would* have
charged, unpriced requests are left out of the total and counted, and no rate is invented.

The three pre-coding probes changed the design in two places:

- **P1 — how a ★ module is discovered.** By **presence on disk**: `discover_features()` in
  `headwaters/core/features.py` walks `pkgutil.iter_modules` over the `headwaters.features`
  package, imports each subpackage by name and calls its `register(registry)`; a
  `headwaters.plugins` entry point is the second path. So "disabling the feature removes it
  cleanly" is satisfied by deleting the folder (discovery finds nothing) **and** by
  `features: {ledger: false}` (registered but `enabled()` gates `plugins_for()`). Both are tested.
- **P2 — what rates the catalog carries.** Per-model, and dated: `ModelEntry` refuses a price
  without a `price_date`. The seed catalog has exactly one paid dated model (`claude-sonnet-4-5`,
  $3/Mtok in, $15/Mtok out, 2026-11-02) and four unpriced local Ollama models. `subscription_rates`
  carries only `claude-pro` at $20/month with `included_credits: null` — **there is no dated
  Copilot/credit rate**, so the packet's optional "subscription credits avoided" estimate is left
  out rather than given an invented rate (FU-501-1).
- **P3 — existing counterfactual code.** `outcomes.counterfactual_usd` has existed since
  migration 1 but nothing wrote or read it, and no `counterfactual` / `reference_model` / `savings`
  calculation existed anywhere. The calculator is built once, here; the token-cost arithmetic is
  shared with the router through `router_log.tokens_cost()`, so the two numbers cannot disagree.

## Assumptions

- A-xxx added to docs/ASSUMPTIONS.md: none — no new assumption was needed, because every rate the
  ledger prices with is read from the active catalog rather than assumed.
- `outcomes.cost_usd = 0.0` means "priced and free" (a local or free-cloud model); `NULL` means
  unpriced. Only `NULL` is excluded from the estimate.
- The counterfactual is computed at read time from the stored tokens and the current catalog rate,
  rather than persisted per request: rates change, and a stored figure would silently age. FU-501-3
  covers persisting it with the rate date.
- `ledger.reference_model` unset means "the frontier reference", resolved as the catalog's most
  expensive priced model by `price_out`, then `price_in`, then id — chosen from data, never a slug.
- `ledger.window_days` (default 30) bounds the report; `week` is the last 7 days; days are UTC.
- Free/local percentage uses `models.tier`; a decision whose model has no `models` row is tier
  `unknown` and is not counted as free.
- "Verification catches" from v3 §4.9 is not part of this ticket: no verification data is recorded
  yet, so the summary shows no such count.

## Deviations

- **The packet's model/effort line and its "Run ruff, mypy, pytest" step are superseded** by this
  session's instructions: no mypy and no full suite; one targeted pass instead.
- **The subscription-credits estimate is not built** (packet marks it optional, and P2 shows there is
  no dated credit rate to price it from). Follow-up FU-501-1.
- **`headwaters_status` no longer gates savings on the feature id.** The packet and FU-205-6 describe
  savings appearing "only if a `DashboardPlugin.render_summary()` exists under `ledger`"; the shipped
  code asks `registry.dashboard_summary()`, which is a superset — the ledger is still the only
  contributor, and core no longer has to name a feature it must not import.
- **Two existing tests changed their premise** (`tests/test_more_status.py`): a real engine now has a
  real ledger, so "no savings" is a flag-off state rather than the default, and the stub-plugin test
  registers under its own id because two features cannot share `ledger`.
- **`FeatureRegistry` grew two seams** (`services=`, `provide_services()`) and a `dashboard_summary()`
  helper. This is core surface added for a ★ feature; without it the only alternative was importing
  `headwaters.features.*` from core, which import-linter forbids.
