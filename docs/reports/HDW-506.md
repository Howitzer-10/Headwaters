## Summary

`vscode-extension/` is now a real TypeScript extension: it registers a
`vscode.LanguageModelChatProvider` under the vendor `headwaters`, discovers the daemon's gateway port
and bearer token from the daemon state files (`%LOCALAPPDATA%\Headwaters`, or `HEADWATERS_HOME\state`
like `headwaters/core/paths.py`), reads the model list from `GET /v1/models`, and streams
`/v1/chat/completions` through to VS Code as text parts and tool-call parts. It is a thin client: no
routing, no model selection, no fallback, no retries, and nothing but loopback HTTP.

The ticket's honesty problem is resolved on the gateway side, which is why there is a Python half:
a virtual model is a routing alias, so its context window, tool support and vision support cannot be
measured, and `LanguageModelChatInformation` still demands numbers. `headwaters/gateway/models.py`
now computes a **declared capability floor** per alias from catalog + rules data and publishes it on
every `/v1/models` card; the extension copies it verbatim and holds no per-model numbers of its own.
Nothing was invented per model.

## Deviations

- **Model/runtime:** the packet names Sonnet/High; this session ran DeepSeek v4.1 Flash at high
  reasoning effort per owner policy.
- **Python touched on purpose.** The capability floor had to come from catalog + rules data, so
  `headwaters/gateway/models.py` and `openai_routes.py` gained the floor and
  `tests/test_gateway_model_capabilities.py` covers it (the ticket allows exactly this).
- **Vision is advertised `false` even when the gateway says `image_input: true`.** `@types/vscode`
  1.104 has no content part that can carry an image into `provideLanguageModelChatResponse`, so
  claiming vision would be a lie the API cannot honour. The gateway keeps publishing `image_input`
  for the day a VS Code version can use it (FU-506-2).
- **Minimum VS Code is pinned from the typings, not from release notes** — see A-VS-6.
- **The model list is cached until `headwaters.refreshModels` runs.** A daemon that starts after VS
  Code does is not picked up automatically (FU-506-4).
- **No packaging.** No `vsce`/`.vsix` step and no CI job for the extension; the repo CI is Python-only
  (FU-506-5).
- The earlier `progress` note to the coordinator was recorded in this session's tool history but not
  delivered as a message, so the pre-coding summary (goal, files, capability decision) is repeated in
  the handoff.
