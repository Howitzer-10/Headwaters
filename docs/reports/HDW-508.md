## Summary
Adds `headwaters.features.usage_report`, a ★ package that builds a fixed-shape weekly aggregate payload, shows it byte-for-byte before consent, and can only send it over an https endpoint the user set themselves — off by default, `report.endpoint: null`, and no socket opened while it is off. Alongside it: `headwaters report` (`status`/`preview`/`enable`/`disable`/`send`/`endpoint`/`survey`), an unconditional row in `headwaters doctor` and on the status page that names the report even when the package is absent, a daemon sweep that only fires when the switch is on and the interval is due, `headwaters feedback` with an optional redacted doctor bundle, and a 7/30-active-day survey prompt capped at two and silenced forever by a dismissal. `Rules.telemetry` stays `Literal[False] = False` and `docs/PRIVACY.md` is untouched: as shipped (off, `endpoint: null`, no socket) the "No telemetry" notice is not yet false.

## Assumptions
- A-508-a: `telemetry: Literal[False]` means "no automatic background reporting"; the opt-in report is a separate per-feature key (`features.usage_report` + `report.*`) and never touches `Rules.telemetry` or the release gate. Only `core/rules.py:498` and `control/release_gate.py:287-293` read that field, and `render_rules` uses `exclude_defaults=True`, so no `telemetry:` line is ever written.
- A-508-b: the as-shipped notice (`docs/PRIVACY.md`, "No telemetry") is accurate today: off by default, `report.endpoint` defaults to `None`, no socket is opened, and nothing ships a collector URL.
- A-508-c: `decisions.ts` is the active-day source (distinct UTC dates), because it is the only per-day usage record the app writes.
- A-508-d: `httpx` (already a dependency) is the only HTTP client on the send path; `litellm` stays restricted to `core.executor.cloud`.
- A-508-e: consent is versioned by `PAYLOAD_VERSION`, so a payload-shape change requires a fresh preview rather than silently reusing old consent.
- A-508-f: the redacted bundle from `control/bundle.py` is the only attachment mechanism; product feedback never becomes a report field.

## Deviations
- **No wizard or settings screen exists in this build**, so "turned on by the user in the wizard or settings, with a preview" is met through `headwaters report` (preview → enable) plus the unconditional doctor/status rows. FU-508-6.
- **No endpoint ships.** The packet assumes a collector; this build has `report.endpoint: null` and `headwaters report endpoint <url>` (https only). A report can never be posted to a default URL.
- **"scope/engine counts"**: no engine field is recorded anywhere; the recorded analogue is `decisions.surface` (cli | mcp | gateway | tray | other), and it is named `engines` in the payload. FU-508-3.
- **GPU class is not persisted**: it is read live from `HardwareState` and is `unknown` when no daemon/cached state exists. FU-508-5.
- **14-day retention is recorded from now on, not recollected**: `report.first_seen.<id>` is stamped on first payload build, so the field is `null` until a feature has been on for two weeks. FU-508-2.
- **Failovers are approximate** (`decisions.alternatives` mixes failed attempts with untried fallback names), so the field is a bucketed `failover_requests_approx`. FU-508-4.
- **Packet step 3 said "ruff, mypy, pytest"**: the coordinator's instructions supersede that with one limited pass (ruff check + format check on changed files, `lint-imports` once, `pytest --collect-only -q` once, targeted pytest only). No mypy run and no full-suite run were performed, by instruction.
- **`docs/PRIVACY.md` was not edited.** The announcement is a separate release act and `control/release_gate.py` text-matches that file; see FU-508-1.
- Naming: `outcomes.user_feedback` / `set_user_feedback` / the MCP tool "Give feedback on an answer" all mean *rating an answer*. This ticket's product feedback is always spelled "product feedback" in CLI output and is flagged `product_feedback: true, rates_an_answer: false` in `headwaters feedback --json`, so a grep can tell them apart.
