## Summary
The dashboard port now serves one read-only page built from the daemon's own state: scope and locks,
walls with their end times, the warm model, the last ten routing decisions (metadata only) and the
core/★ feature list with the ★ legend. `headwaters/control/status_page.py` reads the state once and
renders the HTML with no script, no form and nothing to click; `headwaters/gateway/server.py` serves
it from a new `LoopbackOnlyApp`, which refuses any request whose `Host` is not loopback (421
`bad_host`) and any non-loopback `Origin` (403 `bad_origin`), so a page on another machine cannot
reach it through a rebound name. The six carried follow-ups are closed with tests rather than notes:
wall subjects read as words (`OpenRouter: paid credits`) in the page, `headwaters status` and the MCP
wall rows; `locks_in_force` and `headwaters pick` read `ScopeDecision.active_locks`, which the
decision log now also stores; the offload penalty is named in the reasons and shown in the page; and
`quota_status` lists local models and tells a wall's provider apart from its key scope.

## Deviations
- **`pick_ports` returns four values.** It used to return `(sock, gateway_sock, ports)`; the
  dashboard socket has to exist before `daemon.json` names its port (FU-201-6), so the shape is now
  `(sock, gateway_sock, dashboard_sock, ports)`. `tests/test_gateway_ports.py` was rewritten for it
  (the three old cases, plus the dashboard binding, the disabled case and the served page), and
  `headwaters/daemon/runner.py` was updated; no other caller existed.
- **A dashboard toggle needs a restart.** `dashboard.enabled` is read once in `pick_ports`, so
  turning the page off (or on) in `rules.yaml` takes effect at the next daemon start; the page
  itself is not a live rule reader (FU-404-3).
- **An existing assertion changed on purpose.** `tests/test_cli_status.py` used to assert
  `"after a balance check"` for a `until=None` wall; that text is what FU-122-4 removes, so the row
  is now a `provider:openrouter:paid` wall and the test asserts `"unknown"` and the absence of the
  old wording.
- **The MCP `provider` field is a display name.** `WallInfo.provider` carries `provider_name(...)`
  (`OpenRouter`), matching the label, rather than the raw id, so a host renders one spelling.
- **The dashboard port is no longer probe-only.** `pick_ports` binds it and the daemon serves the
  page on it; the FU-301-4 note (a probed port the daemon does not hold) no longer applies to the
  dashboard, only to any port that is probed without being bound.

## Follow-ups
- FU-404-1 | page | `headwaters/control/status_page.py` `render_html` | The page is a snapshot: it
  has no meta refresh and no script, so a reader has to reload it. A poll with a `no-store` fetch
  would be an editing-free improvement, and belongs with the ★ dashboard (HDW-503) if that page
  ever grows live sections.
- FU-404-2 | page | `headwaters/core/quotas.py` `wall_label`, `headwaters/mcp/tools/status.py`
  `_wall_info` | A `key:<alias>` wall whose alias the key store does not know still renders as
  `Key "<alias>"` with no provider (`provider=None`), because the alias-to-provider index is the only
  mapping and it may have been removed. Keeping a last-known provider on the wall row would fix it.
- FU-404-3 | daemon | `headwaters/daemon/service.py` `pick_ports` | `dashboard.enabled` and
  `dashboard.port` are read at startup only, so changing either needs a daemon restart; a rules
  reload keeps serving the old socket. A reload that rebinds the dashboard socket is a daemon
  change, not a page change.
