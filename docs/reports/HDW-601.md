## Summary
Added the ★ feature package `headwaters.features.context_engine`, a local symbol index: tree-sitter
extracts definitions, call references, imports and a one-line file summary for ten grammars (Python,
JavaScript/JSX, TypeScript/TSX, Go, Rust, Java, C#, C, C++), stores them in one SQLite file per
workspace under the cache directory, and updates incrementally - by size plus mtime on a scan, by an
explicit path list from a `watchdog` observer, and by `git diff` between the recorded HEAD and the
current one. Nothing leaves the machine and no model is called. The ticket also closed FU-203-4
(`workspace_ignore.py` now reads git's global ignore file, `$GIT_DIR/info/exclude` and ignore files
above the root) and FU-203-7 (`pack_files` decides by size before reading a file). No MCP tool and no
`ContextPlugin` implementation yet: that is HDW-602.

## Assumptions
- Added one row to docs/ASSUMPTIONS.md (Local symbol index, HDW-601): the ten-second ceiling for a 10k-file workspace, with the measurement above as its source. The packet says "within the documented time budget" but no budget is documented anywhere in the repo, so the number is measured rather than invented; see FU-601-2.

## Deviations
- The packet's build list is implemented in full, and no decision contradicted it. D9 (workspace boundary) is honoured more strictly than the packet asks: enumeration never leaves the root, `..` can never enter the pending set, and a symlink is skipped rather than followed (the packet is silent on symlinks), so indexing cannot read a file outside the workspace.
- `FEATURE_SPEC.interfaces` is empty on purpose. The index is a library here; the `ContextPlugin` implementation, the MCP tools and the daemon wiring are HDW-602. Registering a plugin now would mean shipping an interface with nothing behind it.
- The time budget is set from measurement because the documented one does not exist (FU-601-2).
- `extract` refuses a language name it does not know before calling `get_parser`, because the grammar pack raises a `DownloadError` (and would try the network) for an unknown name rather than a `LookupError`.
- Python functions defined directly in a class body are reported as `method`, not `function`; the packet only asks for definitions.
- `scan()` returns a sorted list, and `search(prefix=True)` escapes the name before adding its `%`, so a `%` or `_` in a symbol name cannot widen the match.
