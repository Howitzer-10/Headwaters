## Summary
An agentic request that fails a mandatory check now escalates only to a model that is stronger at the task *and* no weaker at tool calls, so the retry cannot hand the caller a model that is worse at the tools the request needs (D10 refinement of 2026-11-01, FU-129-2). When that rule is what empties the pool, the answer comes back flagged `verify_failed` with the note "no stronger model keeps tool strength", so the flag explains itself. Non-agentic requests and the scope and hard filter rules are unchanged; local scope still retries only on local models.

## Files changed
- headwaters/core/router.py: `_redecide` calls the new `_keep_tool_strength` for an agentic escalation; `_keep_tool_strength` drops candidates whose `agentic_tools` score is below the failed model's (missing counts as 0) and adds the note when it empties the pool.
- tests/test_router_escalation.py: five tests for the rule (equal tool score, higher tool score with a lower-tool candidate skipped, nothing as strong at tools flagged with the note, non-agentic unchanged, local scope stays local).
- docs/ASSUMPTIONS.md: one row.
