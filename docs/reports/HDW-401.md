## Summary
API keys now live in the OS credential store (`keyring`, Windows Credential Manager) with the
environment variables as a fallback, and `headwaters keys set|list|remove|test` manages them with a
masked display and one metadata ping per provider. One store (`headwaters/core/keys.py#KeyStore`)
feeds every reader that must agree, which closes the three carried follow-ups: the executor gets
`api_key_for`/`key_alias_for` in the daemon, the engine and the CLI (FU-122-1), and the key-poll
timer and the executor read a key saved by alias instead of only the variable (FU-131-3,
FU-201-4), so a stored key names its own wall `key:<alias>:paid` and lifts it itself. No secret
reaches a log, a decision/outcome row, the SQLite file or CLI output: only alias, provider and
env-var metadata are persisted, and the alias index entry never holds a value.

## Deviations
- The acceptance 402 test uses the generic 402 body (`NO_CREDIT`), not the real OpenRouter body:
  a real OpenRouter 402 keeps the P9 `provider:openrouter:paid` scope by design (HDW-122), so the
  key-scoped `key:<alias>:paid` shape is the generic wall. `tests/test_router_walls.py` still
  proves the P9 shape, untouched.
- `headwaters/core/quotas.py` was on the "files I will touch" list but needed no change: it already
  builds the bearer header from the key it is given. The daemon's env-only `KEY_ENV` map was
  deleted in favour of the store instead.
- `TargetBuilder` keeps its env-only branch when it is built without a store, so every existing
  caller behaves exactly as before (`tests/test_engine.py` untouched).
- Phase A read no SDK source (0 of the 5 allowed turns): the only new external surface was
  `keyring`, settled with one scratch probe plus its own `py.typed` stubs; the three facts are in
  docs/SDK_FACTS.md.
- Not built, deliberately (out of this ticket): the packaging/installer first-run keyring setup and
  every other §C7 packaging item.
